# AgoraFlow

流れて消えない、発信と提案のための次世代SNS

## 概要

AgoraFlowは、短文投稿、スレッド、記事、政策提案、開発ログ、プロジェクトページ、予約投稿、資料化を一体で扱う公開発信プラットフォームです。

個人開発者・政策提案者・小規模プロジェクト運営者が、自分の発信を整理し、予約し、公開し、後から資料として再利用できるWebアプリを目指します。

## 技術スタック

- **Backend**: Ruby on Rails 7.2.3.1
- **Database**: PostgreSQL
- **Frontend**: Hotwire (Turbo + Stimulus)
- **Authentication**: has_secure_password
- **File Storage**: Active Storage (local disk)
- **Deployment**: Render (free tier)
- **Domain**: ops.com

## デプロイメント

アプリは Render でホストされています。

- **本番URL**: https://worldmaster.onrender.com
- **カスタムドメイン**: https://ops.com (設定予定)

### Render サービス

- **Web Service**: Ruby on Rails アプリケーション
- **PostgreSQL**: 無料データベース
- **自動デプロイ**: GitHub main ブランチからのプッシュで自動デプロイ

### デプロイスクリプト

```bash
./bin/deploy-site
```

このスクリプトは以下の処理を行います：
1. テスト実行

============================================================
3. 解決したい課題
============================================================

XのようなSNSでは、投稿がタイムラインで流れて消えてしまいます。
政策提案、開発ログ、アイデア、資料、スレッドが資産化しづらいです。

AgoraFlowでは、投稿を以下のように扱います。

- その場の短文投稿
- 後から読めるスレッド
- プロジェクト単位の更新ログ
- 政策提案ページ
- 記事化されたまとめ
- 外部に提出できる資料

単なるSNSではなく、
「発信 → 整理 → 資料化 → 提案 → 継続更新」
まで扱うWebアプリにしてください。

============================================================
7. 予約投稿・自動投稿キュー
============================================================

このアプリの重要機能として、外部APIに頼らない予約投稿機能を作ってください。

予約投稿の仕様：

- ユーザーは投稿本文と予約日時を指定できる
- 予約日時になったら自動的にAgoraFlow上で公開される
- サーバー側のジョブで定期確認する
- 投稿失敗時はfailedにする
- 再実行できる
- 予約投稿は編集できる
- 予約投稿はキャンセルできる

1時間おき投稿キューの仕様：

- ユーザーが複数の投稿文を登録する
- 開始日時を設定する
- 投稿間隔を設定する
- 初期値は60分
- キューの順番に投稿する
- 自動投稿中は次回投稿予定を表示する
- 一時停止できる
- 再開できる
- すべて投稿し終えたらcompletedにする

安全設計：

- 同じ本文の連投を警告
- 同じURLの連投を警告
- /admin を含むURLを警告
- メンションを含む投稿は警告
- 280文字を超えてもAgoraFlow内投稿は可能だが、短文モードでは警告
- 外部SNSへの投稿はMVPでは行わない

Ruby on Rails + PostgreSQL

理由：
- フロント表現がしやすい
- API設計とUI開発がしやすい

ただし、既存プロジェクトの構成がある場合は、それに合わせてください。
勝手に不要なフレームワーク変更をしないでください。

============================================================
18. バックグラウンドジョブ
============================================================

予約投稿の公開処理が必要です。

MVPでは以下のどれかで実装してください。

Railsの場合：
- Active Job
- Solid Queue
- cron
- whenever
- sidekiqは必要なら使用

Node/Nextの場合：
- cron
- node-cron
- queue worker
- server actionではなく、定期実行できる仕組み

処理内容：

1. scheduled_postsからscheduled_at <= nowかつstatus='scheduled'を取得
2. 対象postをpublishedにする
3. published_atを設定
4. scheduled_postsをpublishedにする
5. posting_queue_itemsもpublishedにする
6. posting_queuesのnext_run_atを更新する
7. エラー時はfailedにする
